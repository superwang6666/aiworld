# 标签生成功能修复报告

## 问题诊断

在第四步生成规则后为20条规则生成标签时出现错误。经过检查,发现以下问题:

### 1. API响应格式不匹配
**位置**: `app/api/tags/generate/route.ts`
- **问题**: API返回 `{ results }` 格式
- **期望**: 前端期望 `{ rules, updatedWeights }` 格式
- **影响**: 前端无法正确接收带标签的规则数据

### 2. 缺少必需参数
**位置**: `app/page.tsx` 第268-275行和304-311行
- **问题**: 调用 `/api/tags/update-weights` 时没有传递 `currentWeights` 参数
- **影响**: API无法更新标签权重,导致400错误

### 3. 响应字段名称不一致
**位置**: `app/api/tags/update-weights/route.ts`
- **问题**: API返回 `updated_weights` (下划线命名)
- **期望**: 前端期望 `updatedWeights` (驼峰命名)
- **影响**: 前端无法正确读取更新后的权重

## 修复内容

### 1. 修复标签生成API (`app/api/tags/generate/route.ts`)

**改动**:
- 修改请求参数,新增 `tagWeights` 参数
- 修改响应格式为 `{ rules, updatedWeights }`
- 将标签结果直接应用到规则对象上
- 合并LLM生成的新标签到权重映射中

**修复后的流程**:
```typescript
// 请求
POST /api/tags/generate
{
  rules: WorldRule[],
  tagWeights: Record<string, RuleTag>
}

// 响应
{
  rules: WorldRule[],  // 带标签的规则
  updatedWeights: Record<string, RuleTag>  // 更新后的权重
}
```

### 2. 修复权重更新API (`app/api/tags/update-weights/route.ts`)

**改动**:
- 修改响应字段名从 `updated_weights` 改为 `updatedWeights`

### 3. 修复前端调用 (`app/page.tsx`)

**改动**:
- 第268-275行: 添加 `currentWeights: tagWeights` 参数
- 第304-311行: 添加 `currentWeights: tagWeights` 参数
- 第214-240行: 添加调试日志,便于排查问题

## 常见问题排查

### 问题1: 标签不显示
**检查**:
- 浏览器控制台是否有错误
- 检查 `rule.tags` 数组是否为空
- 检查 `tagWeights` 对象是否正确初始化

### 问题2: LLM标签生成失败
**检查**:
- `.env` 文件中是否配置了 `DEEPSEEK_API_KEY` 或 `OPENAI_API_KEY`
- API密钥是否有效
- 网络连接是否正常

**降级方案**: 即使LLM失败,系统仍会使用预定义标签,不会阻塞流程

### 问题3: 权重更新不生效
**检查**:
- 确认 `currentWeights` 参数是否正确传递
- 检查API响应是否返回 `updatedWeights`
- 查看控制台日志确认权重更新

## 技术细节

### 标签生成算法
1. **关键词匹配**: 在规则文本中搜索预定义关键词
2. **LLM补充**: 如果匹配少于3个,调用LLM生成补充标签
3. **权重管理**:
   - 删除规则: 权重 × 0.9 (最低0.1)
   - 确认规则: 权重 + (1-权重) × 0.05 (最高0.95)

### 预测删除算法
- 计算规则所有标签的平均权重
- 删除评分 = 1 - 平均权重
- 评分 ≥ 0.6: 黄色警告
- 评分 ≥ 0.75: 红色高风险
